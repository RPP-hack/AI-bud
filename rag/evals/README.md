# Проверка качества поиска и ответов

Из корня репозитория установите пакет и проиндексируйте демонстрационные документы.

```sh
python3 -m pip install -e ./rag
python3 -m rag index
```

По умолчанию используется учебный профиль `intern-platform`. Запускайте ответы с `--offline`, чтобы воспроизвести проверку на встроенных материалах без обращения к провайдеру.

| Что проверить | Команда | Ожидаемый результат |
|---|---|---|
| Исходный чек-лист | `python3 -m rag ask 'Как настроить avito-cli?' --offline` | Пункт первой недели со ссылкой на таблицу. Команд настройки в источнике нет. |
| Репозиторий команды | `python3 -m rag ask 'Как скачать репозиторий?' --offline` | Шаги из учебной инструкции Platform. |
| Противоречивые правила | `python3 -m rag ask 'Кого позвать на ревью?' --top-k 1 --offline` | Обе версии со ссылками и обращение к наставнику. |
| Устаревший материал | `python3 -m rag ask 'Как проверить фичу на dev-окружении?' --offline` | Срок пересмотра истёк. Нужна актуальная инструкция. |
| Изоляция ролей | `python3 -m rag search MENTOR-482` | Пустая выдача. При добавлении `--profile mentor-platform` видна закрытая памятка. |
| Недостаток данных | `python3 -m rag ask 'Сколько стоит лицензия Jira?' --offline` | Помощник сообщает, что доступные инструкции не отвечают на вопрос. |

В автоматической проверке `test_retrieval_examples` заданы 12 вопросов с ожидаемым первым документом или пустой выдачей. Другие тесты проверяют ограничения по команде и роли, конфликт инструкций, устаревшие источники и корректность ссылок. Проверки запускаются из корня репозитория.

```sh
python3 -m unittest discover -s rag/tests -p test_pipeline.py -v
```

Для оценки ответов с реальной моделью укажите провайдера в окружении, запустите те же вопросы в онлайн-режиме и проверьте, поддерживает ли каждый приведённый источник соответствующее утверждение. [Настройка модели](../README.md#работа-с-моделью)
