# Проверка backend

Актуальный выпуск проверяется единым скриптом `scripts/check_release.py`: Go vet, unit/integration tests с race detector, PostgreSQL, преобразование Go coverprofile в Cobertura и сводный отчёт строк. Команды и отчёт: [покрытие всего приложения](../../docs/COVERAGE.md), [сводка](../../docs/coverage/SUMMARY.md).

Go statement coverage и line coverage — разные метрики; для требования кейса используется второй отчёт. Сгенерированный protobuf исключается. Интеграции создают временные БД; точки входа, адаптеры и mock-сервис остаются в знаменателе.

Сохранение диалогов, изоляция, pending/replay, прерывание ожидания и классификация ошибок проверяются в `tests/integration/conversation_test.go`. Реальный вызов Python дополнительно проверяется с тегом `rag_integration`; полный GUI и внешний провайдер проверяются отдельно. Описание архитектуры: [backend-architecture.md](backend-architecture.md).

## Воспроизведение

```sh
docker compose up -d db
export TEST_DATABASE_URL='postgres://buddy:buddy-local@localhost:55432/buddy?sslmode=disable'
make vet
make coverage
```

`make coverage` выполняет:

```sh
cd services/api
go test -race -count=1 -tags=integration -coverpkg=./... -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```

Профиль создаётся в `../services`. Для просмотра строк и блоков
можно выполнить `go tool cover -html=coverage.out`. CI сохраняет профиль как
artifact и проверяет порог 85% операторов. Сам workflow подготовлен, удалённый
запуск GitHub Actions пока не выполнялся.

В расчёте все пакеты модуля: domain, application, адаптеры, HTTP, конфигурация,
bootstrap, entrypoints, onboarding и имитация сервиса. Стандартный механизм Go
исключает тестовые файлы и зависимости. Генерируемого прикладного кода нет.

## Что означает и чего не означает покрытие

Это покрытие **операторов**, не строк. Отчёт не подтверждает порог строк всего
приложения из исходного кейса. При подключении Python и фронтенда потребуется
согласовать измерение строк, набор учитываемых файлов и общий отчёт.

Запуск и перезапуск процессов проверены отдельным HTTP smoke-прогоном, который
не включён в Go coverage. Поэтому entrypoints и bootstrap в профиле имеют 0%.
Часть аварийных ветвей хранилища также не покрыта. В профиль не подмешиваются
результаты ручной проверки.

Интеграционные тесты проверяют сохранённые записи через свежие экземпляры
репозитория/HTTP-обработчика, транзакционность аудита и конкуренцию. Отдельно
реальный Compose-прогон проверил перезапуск процессов. Это разные уровни проверки.
