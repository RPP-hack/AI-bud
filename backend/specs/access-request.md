# Сценарий: запрос доступа, версия 1

Статус: спецификация ядра; AI-поведение и поиск в этот этап не входят.

## Цель

Стажёр подтверждает конкретную заявку и получает сохраняемый ID/статус внешнего
сервиса. Получение заявки не означает выдачу доступа.

## Данные и права

В демо alex относится к notifications, sam к payments. Каждый может запросить
только `read` к ресурсу своей команды. Пользователь может читать, подтверждать,
отменять и обновлять только собственные предложения. Чужой ID даёт 404.
На создании и перед внешней отправкой Policy повторно проверяет разрешение.

Предложение: resource (1–128 байт), access (read/write на уровне модели),
reason (1–1000 байт, непустой после TrimSpace). Демо-политика запрещает write.
Idempotency-Key: 1–128 байт, непустой после TrimSpace. Parameters неизменяемы.

## Переходы

```text
proposed → submitting → submitted
    ↓          ↓
cancelled    unknown → submitted
```

`submitted` содержит внешний статус `pending`, `granted` или `rejected`.
`pending` может перейти в `granted`/`rejected`. Терминальные статусы не регрессируют.
`submitting` и `unknown` допускают восстановление с тем же внешним ключом.
Нет автоматического утверждения, что тайм-аут означает окончательный отказ.

## Прогресс

| Состояние | Прогресс | Следующий шаг |
|---|---|---|
| proposed | todo | confirm_proposal |
| submitting / unknown | waiting | refresh_request |
| submitted + pending | waiting | wait_for_approval |
| submitted + granted | done | start_local_setup |
| submitted + rejected | blocked | contact_mentor |
| cancelled | todo | create_new_proposal |

## Проверяемые критерии

- Создание предложения не вызывает внешний сервис.
- Подтверждение требует положительную версию, для первого подтверждения — текущую.
- Отмена до отправки не создаёт заявку и запрещает её последующее подтверждение.
- Конкурентные подтверждения приводят к одной внешней заявке.
- Повтор создания с тем же ключом/параметрами возвращает прежний ID.
- Тот же ключ с другими параметрами даёт конфликт.
- Чужая заявка недоступна; модель/JSON не могут изменить Actor.
- ID и статус заявки сохраняются в PostgreSQL и читаются после перезапуска.
- Потерянный ответ не создаёт ложного успеха: unknown или submitting восстанавливаются.
- Прогресс done появляется только по внешнему granted.
- Аудит и изменение состояния фиксируются одной транзакцией.

## Связанные проверки

`access/domain/request_test.go`: валидация и переходы.
`access/application/service_test.go`: права, конкурентность, отмена, потеря ответа.
`transport/httpapi/handler_test.go`: внешний API и строгий входной JSON.
`tests/integration/core_test.go`: реальные транзакции, HTTP-интеграция, повторные
запросы и сохранение данных между экземплярами сервисов.
