# AI-bud

Помощник для адаптации стажёров. В демонстрационном сценарии стажёр Platform получает ошибку 403 в Jira, находит доступную ему инструкцию и отправляет тестовую заявку на чтение проекта BUD. Сценарий доступен через веб-интерфейс; RAG также имеет CLI.

## Запуск всего проекта

Нужны Docker Desktop с запущенным Engine и Docker Compose 2.24+; при первом запуске требуется интернет и место для зависимостей и весов BGE (около 2.3 ГБ только веса). Модель хранится в томе `rag-models`, повторно скачивать её не нужно.

Из корня репозитория создайте локальную конфигурацию, если файла ещё нет:

```sh
cp -n rag/.env.example rag/.env
```

В `rag/.env` заполните `RAG_LLM_API_KEY` своим ключом OpenRouter. Файл игнорируется Git. По умолчанию используется фиксированная бесплатная `nvidia/nemotron-3.5-lightning:free`, рассуждения отключены через `RAG_LLM_REASONING=off`. Бесплатный провайдер может возвращать лимиты; автоматического перехода на платную модель нет. Если выбрана другая модель, проверьте поддержку параметра reasoning (`off`, `low`, `default`).

```sh
docker compose -f docker-compose.dev.yaml up --build -d
```

На CPU первый рабочий вопрос может занимать десятки секунд из-за локального вычисления embedding. После загрузки весов, индексации и готовности API откройте **http://localhost/**. Go API также доступен на `http://localhost:8080`. Python-порты в полном стеке наружу не публикуются. Gateway ожидает сборки фронтенда и готовности API. Посмотреть состояние и причины ошибки:

```sh
docker compose -f docker-compose.dev.yaml ps -a
docker compose -f docker-compose.dev.yaml logs --tail=60 rag-index rag api rpp-buddy-gateway
```

`frontend-build` и `rag-index` завершаются с `Exited (0)` — это нормальные одноразовые задачи. Запуск треугольником в Docker Desktop использует уже созданные контейнеры и может открыть интерфейс до готовности API; страница ограниченно повторяет подключение. После изменения кода или env используйте `up --build`, а не `start`.

Остановка с сохранением БД и весов:

```sh
docker compose -f docker-compose.dev.yaml down
```

### Проверка через GUI

1. Основной пользователь — стажёр Platform. Напишите «Привет» или «Что ты умеешь?»; помощник представится и предложит примеры вопросов.
2. Спросите «Не открывается Jira, ошибка 403». Ожидается ответ по учебной инструкции BUD с источником. Можно уточнить «А к какому проекту?».
3. Нажмите «Подготовить заявку на чтение BUD», проверьте параметры и явно подтвердите отправку. Появятся номер mock-заявки и статус «На согласовании».
4. В «Мои заявки» обновите статус. Имитация сервиса переводит подходящую заявку в выданный доступ примерно через 30 секунд; «Следующий шаг» отражает результат.
5. Вернитесь в чат и обновите страницу: переписка и источники восстановятся. История хранится в PostgreSQL, новый диалог закрывает предыдущий; интерфейс просмотра архива не добавлен.
6. Для проверки ACL раскройте «Демонстрация прав доступа». Стажёр Search видит другие материалы и не может подать заявку BUD; наставнику Platform доступны дополнительные документы. Это тестовые учётные записи, не кабинеты управления сотрудниками.

Режим и число источников не нужно выбирать. Поиск документов доступен в «База знаний». При ошибке генерации можно явно выбрать «Найти инструкцию без модели»; это локальный поиск с показом выдержки, которому всё равно нужны сервер, БД и embedding-модель. Неуспешная попытка сохраняется в истории. Неизвестный результат запроса не повторяет генерацию автоматически.

## Сценарий стажёра

Для локального запуска нужны Python 3.11+, PostgreSQL с pgvector и зависимости локальной модели. Скопируйте `rag/.env.example` в `rag/.env`. Из корня репозитория:

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -e './rag[local]'
set -a
. ./rag/.env
set +a
docker compose -f docker-compose.dev.yaml --profile rag up -d rag-db
python3 -m rag index
python3 -m rag ask 'Не открывается Jira, ошибка 403' --offline
python3 -m rag access
python3 -m rag access --confirm
```

`ask` показывает инструкцию с источником. `access` выводит поля заявки. После подтверждения имитатор возвращает номер и статус `pending`. Повторный вызов `python3 -m rag access` показывает сохранённый результат.

Для запуска через Docker Compose загрузите переменные из `rag/.env`, как показано выше, и выполните команды ниже. Именованный том PostgreSQL сохраняет документы, embeddings и заявки между вызовами.

```sh
docker compose -f docker-compose.dev.yaml --profile rag build rag-cli
docker compose -f docker-compose.dev.yaml run --rm rag-cli index
docker compose -f docker-compose.dev.yaml run --rm rag-cli ask 'Не открывается Jira, ошибка 403' --offline
docker compose -f docker-compose.dev.yaml run --rm rag-cli access
docker compose -f docker-compose.dev.yaml run --rm rag-cli access --confirm
```

Настройки LLM, тестовые профили, поддержку PDF, команды тестирования и получения отчёта покрытия см. в [руководстве RAG](rag/README.md). Источники учебного корпуса и их области видимости перечислены в [манифесте](rag/knowledge/manifest.json).
