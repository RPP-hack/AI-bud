# Формат ответа RAG

Сетевые интерфейсы: [REST/gRPC и запуск](../docs/rag-api.md),
[Protobuf](proto/rag/v1/rag.proto). Go передаёт доверенный контекст сотрудника
Python-сервису по gRPC; внутренний REST использует тот же прикладной слой.

После индексации следующая команда выводит результат той же функции `rag.pipeline.ask`, которую вызывает Python-код. Команда выполняется из корня репозитория с установленным пакетом.

```sh
python3 -m rag ask 'Не открывается Jira, ошибка 403' --offline --json
```

| Поле JSON | Назначение |
|---|---|
| `status` | `answered`, `sources_found`, `insufficient_evidence`, `conflict`, `needs_review` или `conversation` |
| `mode` | Режим формирования ответа |
| `steps` | Утверждения с текстом и массивом `source_ids` |
| `sources` | Разрешённые фрагменты документов по ключам, на которые ссылаются шаги |
| `next_step` | Подсказка о следующем шаге стажёра |
| `model` | Идентификатор модели при вызове провайдера или `null` |
| `action` | Предложение показать черновик заявки (`preview_jira_access`) или `null` |

Python-свойство `GenerationResult.answer` объединяет утверждения, ссылки и следующий шаг для вывода текста. Структурированный клиент получает эти данные из `steps`, `sources` и `next_step`. [Формирование результата](../rag/src/rag/generation.py)

## Интеграция с Go

При подключении Go API определяет сотрудника, роль и команду из авторизованной сессии. Python использует роль и команду как контекст поиска и отбирает разрешённые источники до передачи текста модели. Обработчик подтверждения в Go проверяет параметры и право на отправку, вызывает сервис доступа и возвращает выданные сервисом идентификатор и статус. Кнопку подтверждения следует показывать после предпросмотра полей заявки.

В текущей CLI-демонстрации подготовку и подтверждение заявки выполняет тестовый адаптер. Команда `python3 -m rag access` показывает черновик либо сохранённую заявку, а `python3 -m rag access --confirm` отправляет заявку в имитатор. Оба вызова используют выбранный тестовый профиль. [Спецификация сценария](../docs/rag-sdd.md)

`conversation` — обычная реплика помощника: представление, возможности, уточнение или благодарность. У неё могут быть пустые `source_ids` и `sources`; ответ формируется локально в режиме `rules`. Для рабочих инструкций статус `answered` по-прежнему требует проверяемых ссылок.
