# Frontend: первая задача и доступ к Jira

Источник требований: исходный кейс Авито «AI-buddy: ИИ-наставник для стажёров», страницы 7–12. Один глубоко проработанный сценарий допустим; отдельная HR-система, кабинет наставника и полный трекер онбординга не требуются. Интерфейс реализует сценарий из `rag-sdd.md`.

| Требование | Реализация |
|---|---|
| Контекст команды и права | `/api/me` определяет роль и команду. Смена учебного профиля размонтирует предыдущий интерфейс, очищает диалог/источники/заявки и отменяет ожидание ответа. API повторно проверяет права. |
| Путь от вопроса до результата | Вопрос Jira 403 → инструкция с цитатами → подготовка полей → сохранённый предпросмотр → отдельное явное подтверждение → номер и статус сервиса. |
| Этапы, статусы, следующий шаг | «Следующий шаг» показывает стадии выбранного процесса и серверную проекцию `/api/onboarding`. Список и карточка показывают все состояния заявки и pending/granted/rejected, без выдуманного процента общего онбординга. |
| Реальный результат действия | Отображаются только ID, статус и параметры, возвращённые Go. GET списка восстанавливает заявки после перезагрузки. `pending` не объявляется выданным доступом. |
| Неопределённость источников | `conflict`, `needs_review`, `insufficient_evidence` имеют отдельные подписи; показываются все ссылки, дата просрочки и эскалация из ответа. |
| Синтетические данные | Учебная среда и профили отмечены явно; каждый источник показывает demo/public, demo не называется регламентом Авито. |
| Быстрый интерфейс | Локальные переходы и ввод синхронно обновляют React-состояние. Внешние запросы асинхронны; есть ожидание, отключение повторной отправки и ручной повтор. Нет автоматических платных LLM-повторов. |
| Ошибки интеграции | 202 сохраняет неопределённость; 409 требует обновить версию; 403 не выдаётся за успех. Повтор неизвестного результата использует `/refresh` существующей заявки. Повтор предпросмотра после сетевого сбоя сохраняет ключ и параметры до успешного ответа. |
| Совместимость со стеком | React + TypeScript, типизированный отдельный API-клиент. Gateway ожидает завершения сборки Vite и готовности Go API. Единственный публичный HTTP-сервер интерфейса — существующий Caddy. |
| Покрытие | Vitest, Testing Library, покрытие V8 с LCOV; порог lines/statements/functions 81%, branches 75%. Общий порог проекта считается по суммарным покрытым/исполняемым строкам всех компонентов, а не средним процентов. |

Клиент использует все публичные REST-операции Go: identity, answer, search, list/get/propose/confirm/cancel/refresh requests, onboarding, health, ready. Python REST является внутренним интерфейсом делегирования доверенной роли и не публикуется через gateway: те же операции поиска/ответа доступны браузеру через Go → gRPC. Ключ LLM и RAG_SERVICE_TOKEN никогда не входят в сборку.

Ответы и цитаты рендерятся как текст React, без HTML/Markdown исполнения. Оригиналы разрешены только по http(s) без userinfo, с `noopener noreferrer`. Реальные инструкции, цены, HR-операции и отсутствующие API не имитируются на клиенте. История диалога, источники и ошибки хранятся в PostgreSQL через модуль диалогов Go; заявки также сохраняются на сервере.

Проверка пользы и пилот — в `rag-sdd.md`. Прохождение демо и тесты не являются доказательством эффекта на реальных стажёрах. Сквозной путь должен быть дополнительно проверен на полном Compose-стеке; изолированные тесты используют контрактные ответы, а не доказывают доступность сервисов.

## Уточнения поведения выпуска

- Основной профиль — стажёр Platform. Переключение роли/команды находится в раскрывающемся блоке демонстрации прав, не является корпоративной авторизацией или кабинетом наставника.
- Пользователь не настраивает `top_k` и режим генерации. Вопросы идут в `llm`, поиск по базе знаний остаётся отдельным разделом. После сохранённой ошибки генерации доступен явный поиск инструкции без модели.
- `conversation` показывает локальную реплику без обязательных цитат и предлагает поддерживаемые вопросы. Рабочие ответы сохраняют ссылки.
- Временный ответ gateway 502/503 отображается как недоступность/запуск, а не неправильный JSON. Стартовое подключение повторяется ограниченное число раз, без повторов LLM-запросов.
- При закрытии раздела прекращается ожидание браузера; Go сохраняет ответ в ограниченном по времени контексте. При возврате pending-ответ восстанавливается опросом, без повторной генерации.
